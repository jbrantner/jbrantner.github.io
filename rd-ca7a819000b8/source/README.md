# Render Deck (source)

Jordan's phone front end for ComfyUI. Blocks in the app build the ComfyUI API graph; Render sends it to the render computer.
Copyright (c) 2026 Jordan Brantner. All rights reserved.

- Live app: https://jbrantner.github.io/rd-ca7a819000b8/
- `comfy-app.html` is the whole app (one file, no doctype; `webbuild.py` wraps it into `../index.html` with the manifest, icons and offline helper).
- Release: edit `comfy-app.html`, run the tests, then `python3 webbuild.py ..` from this folder, commit and push `main`, and check that the "pages build and deployment" Action succeeds.
- `../tags.txt` is the Danbooru tag list behind the prompt suggestions (Illustrious and Pony styles): tag, category, count, aliases, a flag on adult or gore tags (`s` suggestive, `q` nudity, `e` sexual, `g` gore, then `w` when the tag's words have everyday senses too, so the reader takes it only in a plainly adult prompt), and each character's series. Rebuild it with `python3 make_tags.py danbooru.csv` from the a1111 tagcomplete list (link in the script), after `make_series.py` if the series need refreshing.
- `series.txt` (in this folder) is each character's series, made by `make_series.py` from the character tags themselves and the Character Select SAA lists (links and usage in the script).
- `../words.txt` is the English word list the prompt reader checks typos and word forms against (everyday words, other dictionary words, common names). Rebuild it with `python3 make_words.py EnglishDictionary.csv` (needs `pip install wordfreq english-words`).
- Prompt reader (the "Tags from your words" panel, between `READER START` and `READER END` in `comfy-app.html`): splits each comma piece into words, fixes typos only towards tag words (and never a real English word), knows word forms (casting/cast, sat/sit, hands/hand), finds tags whose words are spread over the sentence or turned round (casting an epic magic spell → casting spell; ribbon in her hair → hair ribbon), names characters and adds their series, reads names that are everyday words (link, fern) only when their series is about or they are written as a name, says no to "without glasses", and counts the people (a girl hitting another girl: 2girls; a girl and her little brother: 1girl, 1boy, brother and sister). Adult tags come only from their own words typed in order, or in another form, order or name once an adult word is typed, never from a typo, and everyday senses stay everyday (a sperm whale, nude lipstick, a naked blade, stripping wallpaper). A prompt that mentions children (child words, ages under 18, school years, and their typos) gets no adult tag, no adult word sent and no rating. The Rating row sets the style's rating tag from the words (Illustrious general → sensitive, nsfw or explicit, with nsfw taken out of the negative; Pony rating_questionable or rating_explicit), with a tap to keep the style's own. The user's own characters (🧍 Characters) and LoRA activation words go as typed and are counted, never read as a Danbooru character. The words with no tag go as words; Send as tags off sends the prompt as typed.
- `../chars.txt` says how often each character is drawn as a girl, boy or other, so the app can add 1girl / 2girls / 1boy / solo for the people named in a prompt. Rebuild it with `python3 make_chars.py` (asks Danbooru once per character; it resumes if stopped).
- Bump `APP_VERSION` in `comfy-app.html` on every release so a phone that resumes the app offers the update.
- Tests: `node tests/t_tags.js` runs the prompt reader on about 650 prompts (typos, word forms, characters, people counts, adult tags kept out of innocent prompts, the children guard, the rating) and checks its speed; `node tests/t_reader.js` runs it on 849 more SFW and adult prompts in `tests/fixtures/reader_cases.json` that must keep reading right; `NODE_PATH=$(npm root -g) node tests/t_flow.js`, `tests/t_lib.js`, `tests/t_queue.js`, `tests/t_farmapp.js`, `tests/t_draftfarm.js`, `tests/t_hidden.js`, `tests/t_chars.js`, `tests/t_pose.js`, `tests/t_suggest.js`, `tests/t_orbit.js` and `tests/t_3d.js` (needs Playwright), and `python3 tests/t_farm.py` for the helper's farm (and `tests/t_download.py` for resuming downloads) (needs aiohttp). It runs the app at phone size against a pretend ComfyUI and checks every graph against ComfyUI's node definitions; `t_queue.js` runs the queue across two pretend computers.
- Queue: every computer under ⚙ › Render computer takes renders while it's on and switched on in the queue (☰). Each render goes into the least busy computer's ComfyUI queue, so it keeps going when the app closes; while the app is open a free computer takes a render waiting on the other. Models and LoRAs are shared between the computers automatically through the helper's `/renderdeck/sync`.
- Draft mode (✎ by Render): each render stops at Painting › Draft stops at (about 45% of the steps by default) and saves to `RenderDeck/drafts`. Its picture is the clean guess at that step, like the live preview. Drafts wait under the main list; tick the good ones and Finish, which queues the full render built with the draft (same seed and settings, so it grows from the same start) with the finishing pass, upscale and face fix. It reruns the first steps rather than copying a saved latent between computers, so either computer can finish it.
- ⚡ Auto run (v.72, Jordan 2026-10-20: 'turn it on before I go to bed'): Run until Angles / Training shots / Picked set / Finished LoRA, then ▶ Start. The app builds its own graphs (turnaround; one per training shot with @SIDE/@BACK for the angle pictures the run finds; the quality pass with @IMG/@TAGS when it redraws) and POSTs them to the MiniMax PC's helper /renderdeck/auto/start. The helper (render_deck_auto.json, survives a ComfyUI restart) queues them on its own ComfyUI, finds the angles (silhouette width, as findSides) and the two sharpest moments per shot with PyAV + numpy, saves frames 1.5x (or redraws), picks the set (angles kept; shot frames by sharpness, blurry under 0.35x median and dHash near-repeats dropped, up to 30), writes captions to kohya\data\<trigger>\10_<trigger> and RenderDeck/datasets/<trigger>, then trains with kohya sd-scripts (found under %LOCALAPPDATA%\Comfy-Desktop\kohya; fp8_base, cached latents and TE outputs, Adafactor 1e-4, dim 16/alpha 8, unet only, 1200 steps, a save every 400, killed after two readings over 87 C; the farm skips that PC meanwhile) into models/loras as <trigger>_auto_<date>.safetensors. The app polls /renderdeck/auto while the character sheet is open and puts the run's angles, shots and picks on the card (autoImport; images as 'sub/file.png [output]'). Tests: tests/t_auto.py (helper, pretend ComfyUI and kohya), t_pipe.js.
- Character card layout (v.70, Jordan 2026-10-20): the original reference picture at the top; name, tags; then folding steps 1 · Turnaround and angles (Build it all), 2 · Training shots, 3 · Training set, and 🛠 More tools (every picture with its angle, Make other angles, the turnaround video by hand). Only the current step (curStep: build until the angles exist, then shots until one is made, then the set) is open; tapping a header opens it (CH.step). The colour row and the 3D model block are gone from the card (3D code kept, unused).
- Characters (🧍 by Recipe): a card per character with a name, Danbooru tags, a colour and pictures of them from several angles (front, ¾, left side, right side, back, face). Add a picture from the phone, or 🧍 Add to a character under any render. Make other angles turns the picked picture into the missing angles with Qwen-Image-Edit (its Lightning LoRA when there is one) on the computer that has it, copying the picture there first; each result joins the character and saves in `RenderDeck/characters/<name>`. Hidden has its own characters. A picture marked Reference (the default for new pictures) only makes a full-body front, which is then picked so the other angles come from it. Drag across the big picture to turn the character around (the far side is the near side mirrored). ✨ Suggest tags reads the pictures with Florence-2 PromptGen (comfyui-florence2) on Render and offers the Danbooru tags it saw that aren't on the card; the first use downloads the model (1.1 GB) after asking. 🧊 3D model: Pixal3D (ComfyUI's own TRELLIS.2 nodes, Render) builds a coloured .glb from the newest Front, Side and Back pictures (cut out with BiRefNet), saved in `RenderDeck/characters/3d`, shown on the card with model-viewer. The 3D graph follows ComfyUI's own Pixal3D template (CFGOverride + RescaleCFG, upsample 1536, RemeshMesh 768, Decimate 200k), unwraps the mesh (UnwrapMesh, BakeTextureFromVoxel, ApplyTextureToMesh, 2048) and saves the four cut-out views and their masks in `3d/views`; the app then paints the texture from those views in the browser (WebGL2, rig cameras fov 20 at 1.1·0.5/tan 10°, outline fitted to 1/1.1 of the frame, depth tested per view, normal-weighted, seams grown outward; unseen spots keep Pixal3D's colour) and uploads the painted .glb to that PC's input folder (rd3d_<id>_<t>.glb). 🎨 Paint from the pictures redoes it. Shape from: Hunyuan3D-2mv (default when present; core Hunyuan nodes, hunyuan3d-dit-v2-mv_fp16 4.6 GB in checkpoints, views cut out on white, 20 steps cfg 7.5, octree 256, surface net, then a blank 1024 texture map for painting; HY_YAW is its facing, unverified) or Pixal3D. Test: tests/t_paint3d.js. Get the 3D model fetches the one missing file (pixal3d_multiview_int8_convrot, 5.6 GB) through the helper into diffusion_models. 🎬 Turnaround video: MiniMax H3 (Turbo model + 4-step ref2v Turbo LoRA when present, else the base model at 20 steps) on Render turns the character around once (576×1024, 124 frames) from the newest Front, or the Reference when there's no front; the picture is the reference; a Front is also pinned (padded, not cropped) as the first and last frame, a Reference is not, so the clip opens on a clean full-body front (Front is in the frame picker). Saved as an mp4 in `RenderDeck/characters/turn`. On the card, pick ¾ view / Right side / Back / Left side (jumps to 12.5/25/50/75% of the clip), slide to the best frame and ＋ Add it: the frame is grabbed in the browser and uploaded to that PC as a new picture. 🧊 Turnaround from the 3D model (when the card has a model and the PC has minimax_h3_fun_controlnet in model_patches): the phone spins the grey model once to their left (orthographic, 86% of the height, 576×1024, 124 frames), draws each frame as white outlines on black (silhouette, normal creases, depth steps), packs them as an MJPEG .avi (rdspin_<id>_<t>.avi, uploaded to the PC's input folder), and MiniMax H3 (the Video model picked on the card, Turbo 4 steps by default) paints it through LoadVideo → GetVideoComponents → MiniMaxH3FunControlNetApply at 1.0 with the Front picture as the reference and nothing pinned. The spin's fit {cx, cy, cz, s, r} is kept on the clip; 🎨 Paint from the turnaround (turnViews) grabs six frames 60° apart and bakes them with those orthographic cameras (white background and 2.5 px in from it ignored). New models are no longer painted automatically. 🪄 Build it all (no 3D since 2026-10-19, at Jordan's ask) runs from the given Reference or Front picture (kept as the look): turnaround with no style LoRA → Pick the angles (the silhouette's width per frame, every 2nd frame: narrowest in 14–36% and 64–86% are the right and left sides, the middle of the widest stretch half way between them the back, the widest in the first 8% the front, ¾ views half way to the sides; six frames uploaded as views marked pipe with slot, raw and caption 'standing, a-pose, full body, simple background, white background'; a given Front is kept) → Quality pass (redrawGraph: 1.5× lanczos, then UltimateSDUpscaleNoUpscale with the Illustrious checkpoint in 1024 tiles, no LoRA, the card's tags, at the card's Quality pass strength: Bigger only (no redraw) by default since Jordan found those most consistent, Light 0.2, or Stronger 0.3; 0.35 changed the Librarian's hair, eyes and lips; saved in characters/angles). Progress bar with step and time left; state in c.pipe, a run left mid-way picks up when the card opens; ↻ Redo from here per step; a picked frame can be swapped from the turnaround (and is redrawn). 🎞 Training shots (all clips go into the PC's ComfyUI queue at once, so they render with the app closed; frames are picked while the app is open, or when the card is next opened; sh.pid/prefix per shot; Stop takes the unstarted clips out of the queue): one line per action ('what they do | tags', 12 calm starters): MiniMax H3 ref2v (the card's Video model, no style LoRA) from the picture, a side and the back (<Picture 2/3> named in the prompt), the two sharpest frames at least 24 frames apart (Laplacian variance, every 4th frame after 0.5 s; c.shotN, default 2) go through the same quality pass and join the card as References carrying the shot's tags (v.cap, v.shotN, saved in characters/shots). Training set picker: each thumbnail has a ✓ at the bottom left that keeps it in the set or leaves it out (v.noTrain); tapping the thumbnail opens the picture viewer (mode 'tset') to swipe through them with a big ✓ Keep / ○ Left out button at the bottom left and the kept count at the top; a meter counts the picked ones against 15–30 (under 10 too few, over 40 too many) and counts close-ups, side, back and action pictures, naming what's thin. 📦 Save the training set captions views with v.cap and, when the card has Build it all angles, leaves out the raw turnaround frames. Test: tests/t_pipe.js. 📦 Training set: every picture on the card plus 12 turnaround frames (every 30°) are uploaded (type output) to RenderDeck/datasets/<trigger> with starter .txt captions (trigger, 1girl/1boy from the card tags, solo, angle: from side / from behind, background); the design tags are left out so the trigger learns them. ✍️ Caption with the tagger: Florence-2 PromptGen (prompt_gen_tags) reads each saved picture ('<dir>/<file> [output]'); look tags on the card or seen in at least 60% of the set are dropped (design), angle guesses are replaced by the app's, the rest is appended to the starter caption, with rules from the first real set: worn-or-not tags (nude, barefoot, nipples…) always stay; body and hair tags always go; character/series/artist/meta tags never go in; turnaround frames (starter: standing, a-pose, full body, white background) only take worn-or-not and face/gaze tags, and back views no face tags; 1girl/1boy comes from the tagger when the card lacks it. Repeated pictures (same bytes) are left out when saving the set and when training. The captioner is the WD EVA02 tagger when the set's PC has the helper's /renderdeck/tagger (SmilingWolf/wd-eva02-large-tagger-v3 via onnxruntime on the CPU, padded square on white, BGR 448; general tags at 0.35; the first use asks to download 1.26 GB into models/wd_tagger and shows progress); Florence-2 PromptGen otherwise. Test: tests/t_tagger.py. 🎓 Train the LoRA (Render by default, or Main; any PC that's on with ComfyUI's core training nodes): the set is fitted to about a megapixel in sizes of 64 (PNG, centre crop) and copied with its captions into that PC's input folder datasets/<trigger>_<stamp>, then LoadImageTextDataSetFromFolder → MakeTrainingDataset (the recipe's checkpoint, else oneObsession) → ResolutionBucket → TrainLoraNode (steps 100 a picture, 1000–2500, editable; rank 16, AdamW 1e-4, bf16, gradient checkpointing, bucket mode) → SaveLoRA in RenderDeck/loras. The newest <trigger>_<steps>_steps_NNNNN_.safetensors since the start is fetched and posted to each online PC's /renderdeck/upload?kind=loras under a new name (<trigger>_<yymmdd>_<xyz>.safetensors). A lost history (restart) is checked against the queue and the file. On a card under 15 GB (from /system_stats; both laptops are 8 GB) TrainLoraNode runs with offloading on and pictures are fitted to about 768×768: the first real run (Laura, 2026-10-19) ran out of graphics memory after 2 minutes with offloading off. Test: tests/t_turn3d.js.
- 📷 Change angle (under any render, in both picture viewers, and as a Change angle block in Add a block; the block is a tool, not part of the render, and shares the sheet's state, with 📱 Pick a picture and 🖼 Use the render on screen): the picture sits in the middle of 8 arrows (the way the camera goes), with Round by 45–180° and Up/Down by 20–80°. 🎬 Make the orbit sends it to the computer with MiniMax H3 FL2V (minimax_h3_fl2va + the fl2v Turbo 8-step LoRA, 8 steps, res_multistep): the picture is the first frame on a canvas of its own shape (576 Quick or 768 Sharper short edge), 124 frames, and the prompt asks for one camera move round the frozen scene, reaching the new angle by 4 s and holding (a long "everything stays the same" prompt barely moved the camera in the Render test). Without an FL2V model it uses the hybrid Turbo with the picture as reference, pinned at frame 0. Saved in `RenderDeck/angles/orbit`. Slide to a frame (starts on the last), ◀ ▶ step one frame, ✨ Finish this frame grabs it in the browser, uploads it and redraws it 1.5× with the Illustrious checkpoint at Light 0.2 (or Bigger only / Stronger 0.3) while a union ControlNet (ProMax, SetUnionControlNetType anime line art, AnimeLineArtPreprocessor, 0.8) holds the shapes and a second ProMax in tile mode (the frame itself, 0.6) holds its colours and small details (line art alone washed the colours out and changed eye colour at 0.2), cfg 4, then KJNodes' Color Match (mkl) puts the frame's colours back when that computer has it; saved in `RenderDeck/angles/finished` and put at the front of the strip. The orbit goes to a free computer first (then the one with FL2V, then the shorter queue), and says when it went elsewhere because the other was busy. The bar also shows "Waiting behind N other jobs" from that computer's /queue, and "taking longer than the usual N min" once past the estimate with no steps. Making the orbit and the touch-up show a live bar: they are queued with the app's client id, so ComfyUI's websocket sends their sampler steps (LIVE / liveMsg / liveEta); time left = measured seconds per step for the steps to go plus a quarter of the sampling time for decoding and saving, and the kit's estimate before the first step. Each workstation keeps its own (S.orbitN / S.orbitH), with the last 8 orbits under Earlier orbits; an orbit being made can't be swapped out, and one that finishes while the app is closed is picked up when it opens; Hidden saves in `Hidden/angles`. The same chain is the ComfyUI-Camera-Orbit node pack on Render.
- Pose board (a recipe block): 3D OpenPose figures (y up, ground at 0, a figure about one unit tall) seen through a camera you orbit by dragging the empty board, or with Front/¾/Side/Back/Above/Below and Zoom; the picture sent is what that camera sees, with the face points OpenPose would not see (looking away, the far eye/ear in profile) left out. The board draws them as mannequins with a round head and a face. Figures are dragged on the phone (the neck moves a whole figure, a joint drags the joints below it), from starter poses, with mirror and size. Each figure can be given a character. The board is sent as an OpenPose picture to the chosen ControlNet (a union one like ProMax gets SetUnionControlNetType openpose), ending at 65% by default. Each figure with a character gets that character's tags in its own area of the picture (ConditioningSetArea + ConditioningCombine over the whole prompt), and the whole prompt gets the count tags (1girl, 1boy…) from the characters' tags.
- Farm: when the computer named Render has the newest helper, it keeps the queue itself (`/renderdeck/farm`, saved in `render_deck_farm.json`) and hands each render to whichever computer has nothing to do, and keeps the models matched, with the app closed. The app then only adds, cancels and shows renders. Without it the app does this itself while open.

## Setup on the render computer
1. Install Tailscale on the render computer and the iPhone, same account on both.
2. Tailscale admin page > DNS: turn on MagicDNS and HTTPS certificates.
3. Start ComfyUI with `--enable-cors-header "*" --preview-method auto`.
4. Optional, for "Add a model or LoRA": copy `comfyui/render_deck_models.py` into `ComfyUI/custom_nodes/` and restart ComfyUI. It downloads Civitai / Hugging Face links and receives files from the phone (.safetensors only). For Civitai models that need sign-in, put a Civitai API key in `CIVITAI_API_TOKEN` or in `civitai_token.txt` next to the helper.
5. Run `tailscale serve --bg 8188` once and paste the https address it prints into the app (⚙ > Connect).
6. Optional, to share renders between computers: set each computer's ComfyUI output folder (Comfy Desktop's output folder, or `--output-directory`) to the same Dropbox folder, and put this computer's name in `custom_nodes/render_deck_pc.txt` (for example `Output_Main`). The helper then saves into that subfolder, the renders browser shows every computer's pictures, and Delete removes them from all of them (Dropbox's Deleted files can restore them).
7. Hidden (🙈 at the top): a second workstation with its own recipe, strip and renders list. Its renders save into `Hidden` folders (`Output_Main/Hidden/…` with a shared folder) and are left out of the normal renders list (needs the helper from 2026-10-18 or later; older helpers still work, the app filters instead).
7. Optional, so ComfyUI comes back after a crash or reboot and the app can Start / Restart / Close it: run `comfyui/install_agent.ps1` once on each computer (the one-line command is at the top of that file). It installs `render_deck_agent.py`, which runs outside ComfyUI at sign-in and is reached at `https://<computer>.ts.net/agent`.

Download speed (helper, 2026-10-19): ⚙ › Model downloads picks Full speed (default) or Gentle (2 MB/s). The app POSTs /renderdeck/speed {mbps} to each online PC; the helper keeps it in custom_nodes/render_deck_speed.json and every download and PC-to-PC copy is paced by it. The other sync safeguards stay: copies only on need or ⇄ Check now, skipped over a relayed Tailscale link, 30-minute backoff.
