# Render Deck (source)

Jordan's phone front end for ComfyUI. Blocks in the app build the ComfyUI API graph; Render sends it to the render computer.
Copyright (c) 2026 Jordan Brantner. All rights reserved.

- Live app: https://jbrantner.github.io/rd-ca7a819000b8/
- `comfy-app.html` is the whole app (one file, no doctype; `webbuild.py` wraps it into `../index.html` with the manifest, icons and offline helper).
- Release: edit `comfy-app.html`, run the tests, then `python3 webbuild.py ..` from this folder, commit and push `main`, and check that the "pages build and deployment" Action succeeds.
- `../tags.txt` is the Danbooru tag list behind the prompt suggestions (Illustrious and Pony styles). Rebuild it with `python3 make_tags.py danbooru.csv` from the a1111 tagcomplete list (link in the script).
- `../chars.txt` says how often each character is drawn as a girl, boy or other, so the app can add 1girl / 2girls / 1boy / solo for the people named in a prompt. Rebuild it with `python3 make_chars.py` (asks Danbooru once per character; it resumes if stopped).
- Bump `APP_VERSION` in `comfy-app.html` on every release so a phone that resumes the app offers the update.
- Tests: `NODE_PATH=$(npm root -g) node tests/t_flow.js`, `tests/t_lib.js`, `tests/t_queue.js`, `tests/t_farmapp.js`, `tests/t_draftfarm.js`, `tests/t_hidden.js`, `tests/t_chars.js` and `tests/t_pose.js` (needs Playwright), and `python3 tests/t_farm.py` for the helper's farm (needs aiohttp). It runs the app at phone size against a pretend ComfyUI and checks every graph against ComfyUI's node definitions; `t_queue.js` runs the queue across two pretend computers.
- Queue: every computer under ⚙ › Render computer takes renders while it's on and switched on in the queue (☰). Each render goes into the least busy computer's ComfyUI queue, so it keeps going when the app closes; while the app is open a free computer takes a render waiting on the other. Models and LoRAs are shared between the computers automatically through the helper's `/renderdeck/sync`.
- Draft mode (✎ by Render): each render stops at Painting › Draft stops at (about 45% of the steps by default) and saves to `RenderDeck/drafts`. Its picture is the clean guess at that step, like the live preview. Drafts wait under the main list; tick the good ones and Finish, which queues the full render built with the draft (same seed and settings, so it grows from the same start) with the finishing pass, upscale and face fix. It reruns the first steps rather than copying a saved latent between computers, so either computer can finish it.
- Characters (🧍 by Recipe): a card per character with a name, Danbooru tags, a colour and pictures of them from several angles (front, ¾, side, back, face). Add a picture from the phone, or 🧍 Add to a character under any render. Make other angles turns the picked picture into the missing angles with Qwen-Image-Edit (its Lightning LoRA when there is one) on the computer that has it, copying the picture there first; each result joins the character and saves in `RenderDeck/characters/<name>`. Hidden has its own characters.
- Pose board (a recipe block): OpenPose stick figures dragged on the phone (the neck moves a whole figure, a joint drags the joints below it), from starter poses, with mirror and size. Each figure can be given a character. The board is sent as an OpenPose picture to the chosen ControlNet (a union one like ProMax gets SetUnionControlNetType openpose), ending at 65% by default. Each figure with a character gets that character's tags in its own area of the picture (ConditioningSetArea + ConditioningCombine over the whole prompt), and the whole prompt gets the count tags (1girl, 1boy…) from the characters' tags.
- Farm: when the computer named Render has the newest helper, it keeps the queue itself (`/renderdeck/farm`, saved in `render_deck_farm.json`) and hands each render to whichever computer has nothing to do, and keeps the models matched, with the app closed. The app then only adds, cancels and shows renders. Without it the app does this itself while open.

## Setup on the render computer
1. Install Tailscale on the render computer and the iPhone, same account on both.
2. Tailscale admin page > DNS: turn on MagicDNS and HTTPS certificates.
3. Start ComfyUI with `--enable-cors-header "*" --preview-method auto`.
4. Optional, for "Add a model or LoRA": copy `comfyui/render_deck_models.py` into `ComfyUI/custom_nodes/` and restart ComfyUI. It downloads Civitai / Hugging Face links and receives files from the phone (.safetensors only). For Civitai models that need sign-in, put a Civitai API key in `CIVITAI_API_TOKEN` or in `civitai_token.txt` next to the helper.
5. Run `tailscale serve --bg 8188` once and paste the https address it prints into the app (⚙ > Connect).
6. Optional, to share renders between computers: set each computer's ComfyUI output folder (Comfy Desktop's output folder, or `--output-directory`) to the same Dropbox folder, and put this computer's name in `custom_nodes/render_deck_pc.txt` (for example `Output_Main`). The helper then saves into that subfolder, the renders browser shows every computer's pictures, and Delete removes them from all of them (Dropbox's Deleted files can restore them).
7. Hidden (🙈 at the top): a second workstation with its own recipe, strip and renders list. Its renders save into `Hidden` folders (`Output_Main/Hidden/…` with a shared folder) and are left out of the normal renders list (needs the helper from 2026-10-18 or later; older helpers still work, the app filters instead).
7. Optional, so ComfyUI comes back after a crash or reboot and the app can Start / Restart / Close it: run `comfyui/install_agent.ps1` once on each computer (the one-line command is at the top of that file). It installs `render_deck_agent.py`, which runs outside ComfyUI at sign-in and is reached at `https://<computer>.ts.net/agent`.
