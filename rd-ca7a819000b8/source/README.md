# Render Deck (source)

Jordan's phone front end for ComfyUI. Blocks in the app build the ComfyUI API graph; Render sends it to the render computer.
Copyright (c) 2026 Jordan Brantner. All rights reserved.

- Live app: https://jbrantner.github.io/rd-ca7a819000b8/
- `comfy-app.html` is the whole app (one file, no doctype; `webbuild.py` wraps it into `../index.html` with the manifest, icons and offline helper).
- Release: edit `comfy-app.html`, run the tests, then `python3 webbuild.py ..` from this folder, commit and push `main`, and check that the "pages build and deployment" Action succeeds.
- `../tags.txt` is the Danbooru tag list behind the prompt suggestions (Illustrious and Pony styles): tag, category, count, aliases, an `x` on sexual or gore tags, and each character's series. Rebuild it with `python3 make_tags.py danbooru.csv` from the a1111 tagcomplete list (link in the script), after `make_series.py` if the series need refreshing.
- `series.txt` (in this folder) is each character's series, made by `make_series.py` from the character tags themselves and the Character Select SAA lists (links and usage in the script).
- `../words.txt` is the English word list the prompt reader checks typos and word forms against (everyday words, other dictionary words, common names). Rebuild it with `python3 make_words.py EnglishDictionary.csv` (needs `pip install wordfreq english-words`).
- Prompt reader (the "Tags from your words" panel, between `READER START` and `READER END` in `comfy-app.html`): splits each comma piece into words, fixes typos only towards tag words (and never a real English word), knows word forms (casting/cast, sat/sit, hands/hand), finds tags whose words are spread over the sentence or turned round (casting an epic magic spell → casting spell; ribbon in her hair → hair ribbon), names characters and adds their series, reads names that are everyday words (link, fern) only when their series is about or they are written as a name, says no to "without glasses", and never brings up an adult tag unless its own words are typed. The words with no tag go as words; Send as tags off sends the prompt as typed.
- `../chars.txt` says how often each character is drawn as a girl, boy or other, so the app can add 1girl / 2girls / 1boy / solo for the people named in a prompt. Rebuild it with `python3 make_chars.py` (asks Danbooru once per character; it resumes if stopped).
- Bump `APP_VERSION` in `comfy-app.html` on every release so a phone that resumes the app offers the update.
- Tests: `node tests/t_tags.js` runs the prompt reader on about 200 everyday prompts (typos, word forms, characters, adult tags kept out) and checks its speed; `NODE_PATH=$(npm root -g) node tests/t_flow.js`, `tests/t_lib.js`, `tests/t_queue.js`, `tests/t_farmapp.js`, `tests/t_draftfarm.js`, `tests/t_hidden.js`, `tests/t_chars.js`, `tests/t_pose.js`, `tests/t_suggest.js` and `tests/t_3d.js` (needs Playwright), and `python3 tests/t_farm.py` for the helper's farm (and `tests/t_download.py` for resuming downloads) (needs aiohttp). It runs the app at phone size against a pretend ComfyUI and checks every graph against ComfyUI's node definitions; `t_queue.js` runs the queue across two pretend computers.
- Queue: every computer under ⚙ › Render computer takes renders while it's on and switched on in the queue (☰). Each render goes into the least busy computer's ComfyUI queue, so it keeps going when the app closes; while the app is open a free computer takes a render waiting on the other. Models and LoRAs are shared between the computers automatically through the helper's `/renderdeck/sync`.
- Draft mode (✎ by Render): each render stops at Painting › Draft stops at (about 45% of the steps by default) and saves to `RenderDeck/drafts`. Its picture is the clean guess at that step, like the live preview. Drafts wait under the main list; tick the good ones and Finish, which queues the full render built with the draft (same seed and settings, so it grows from the same start) with the finishing pass, upscale and face fix. It reruns the first steps rather than copying a saved latent between computers, so either computer can finish it.
- Characters (🧍 by Recipe): a card per character with a name, Danbooru tags, a colour and pictures of them from several angles (front, ¾, left side, right side, back, face). Add a picture from the phone, or 🧍 Add to a character under any render. Make other angles turns the picked picture into the missing angles with Qwen-Image-Edit (its Lightning LoRA when there is one) on the computer that has it, copying the picture there first; each result joins the character and saves in `RenderDeck/characters/<name>`. Hidden has its own characters. A picture marked Reference (the default for new pictures) only makes a full-body front, which is then picked so the other angles come from it. Drag across the big picture to turn the character around (the far side is the near side mirrored). ✨ Suggest tags reads the pictures with Florence-2 PromptGen (comfyui-florence2) on Render and offers the Danbooru tags it saw that aren't on the card; the first use downloads the model (1.1 GB) after asking. 🧊 3D model: Pixal3D (ComfyUI's own TRELLIS.2 nodes, Render) builds a coloured .glb from the newest Front, Side and Back pictures (cut out with BiRefNet), saved in `RenderDeck/characters/3d`, shown on the card with model-viewer. The 3D graph follows ComfyUI's own Pixal3D template (CFGOverride + RescaleCFG, upsample 1536, RemeshMesh 768, Decimate 200k), unwraps the mesh (UnwrapMesh, BakeTextureFromVoxel, ApplyTextureToMesh, 2048) and saves the four cut-out views and their masks in `3d/views`; the app then paints the texture from those views in the browser (WebGL2, rig cameras fov 20 at 1.1·0.5/tan 10°, outline fitted to 1/1.1 of the frame, depth tested per view, normal-weighted, seams grown outward; unseen spots keep Pixal3D's colour) and uploads the painted .glb to that PC's input folder (rd3d_<id>_<t>.glb). 🎨 Paint from the pictures redoes it. Shape from: Hunyuan3D-2mv (default when present; core Hunyuan nodes, hunyuan3d-dit-v2-mv_fp16 4.6 GB in checkpoints, views cut out on white, 20 steps cfg 7.5, octree 256, surface net, then a blank 1024 texture map for painting; HY_YAW is its facing, unverified) or Pixal3D. Test: tests/t_paint3d.js. Get the 3D model fetches the one missing file (pixal3d_multiview_int8_convrot, 5.6 GB) through the helper into diffusion_models. 🎬 Turnaround video: MiniMax H3 (Turbo model + 4-step ref2v Turbo LoRA when present, else the base model at 20 steps) on Render turns the character around once (576×1024, 124 frames) from the newest Front, or the Reference when there's no front; the picture is the reference; a Front is also pinned (padded, not cropped) as the first and last frame, a Reference is not, so the clip opens on a clean full-body front (Front is in the frame picker). Saved as an mp4 in `RenderDeck/characters/turn`. On the card, pick ¾ view / Right side / Back / Left side (jumps to 12.5/25/50/75% of the clip), slide to the best frame and ＋ Add it: the frame is grabbed in the browser and uploaded to that PC as a new picture. 🧊 Turnaround from the 3D model (when the card has a model and the PC has minimax_h3_fun_controlnet in model_patches): the phone spins the grey model once to their left (orthographic, 86% of the height, 576×1024, 124 frames), draws each frame as white outlines on black (silhouette, normal creases, depth steps), packs them as an MJPEG .avi (rdspin_<id>_<t>.avi, uploaded to the PC's input folder), and MiniMax H3 (the Video model picked on the card, Turbo 4 steps by default) paints it through LoadVideo → GetVideoComponents → MiniMaxH3FunControlNetApply at 1.0 with the Front picture as the reference and nothing pinned. The spin's fit {cx, cy, cz, s, r} is kept on the clip; 🎨 Paint from the turnaround (turnViews) grabs six frames 60° apart and bakes them with those orthographic cameras (white background and 2.5 px in from it ignored). New models are no longer painted automatically. 📦 Training set: every picture on the card plus 12 turnaround frames (every 30°) are uploaded (type output) to RenderDeck/datasets/<trigger> with starter .txt captions (trigger, 1girl/1boy from the card tags, solo, angle: from side / from behind, background); the design tags are left out so the trigger learns them. Test: tests/t_turn3d.js.
- Pose board (a recipe block): 3D OpenPose figures (y up, ground at 0, a figure about one unit tall) seen through a camera you orbit by dragging the empty board, or with Front/¾/Side/Back/Above/Below and Zoom; the picture sent is what that camera sees, with the face points OpenPose would not see (looking away, the far eye/ear in profile) left out. The board draws them as mannequins with a round head and a face. Figures are dragged on the phone (the neck moves a whole figure, a joint drags the joints below it), from starter poses, with mirror and size. Each figure can be given a character. The board is sent as an OpenPose picture to the chosen ControlNet (a union one like ProMax gets SetUnionControlNetType openpose), ending at 65% by default. Each figure with a character gets that character's tags in its own area of the picture (ConditioningSetArea + ConditioningCombine over the whole prompt), and the whole prompt gets the count tags (1girl, 1boy…) from the characters' tags.
- Farm: when the computer named Render has the newest helper, it keeps the queue itself (`/renderdeck/farm`, saved in `render_deck_farm.json`) and hands each render to whichever computer has nothing to do, and keeps the models matched, with the app closed. The app then only adds, cancels and shows renders. Without it the app does this itself while open.

## Setup on the render computer
1. Install Tailscale on the render computer and the iPhone, same account on both.
2. Tailscale admin page > DNS: turn on MagicDNS and HTTPS certificates.
3. Start ComfyUI with `--enable-cors-header "*" --preview-method auto`.
4. Optional, for "Add a model or LoRA": copy `comfyui/render_deck_models.py` into `ComfyUI/custom_nodes/` and restart ComfyUI. It downloads Civitai / Hugging Face links and receives files from the phone (.safetensors only). For Civitai models that need sign-in, put a Civitai API key in `CIVITAI_API_TOKEN` or in `civitai_token.txt` next to the helper.
5. Run `tailscale serve --bg 8188` once and paste the https address it prints into the app (⚙ > Connect).
6. Optional, to share renders between computers: set each computer's ComfyUI output folder (Comfy Desktop's output folder, or `--output-directory`) to the same Dropbox folder, and put this computer's name in `custom_nodes/render_deck_pc.txt` (for example `Output_Main`). The helper then saves into that subfolder, the renders browser shows every computer's pictures, and Delete removes them from all of them (Dropbox's Deleted files can restore them).
7. Hidden (🙈 at the top): a second workstation with its own recipe, strip and renders list. Its renders save into `Hidden` folders (`Output_Main/Hidden/…` with a shared folder) and are left out of the normal renders list (needs the helper from 2026-10-18 or later; older helpers still work, the app filters instead).
7. Optional, so ComfyUI comes back after a crash or reboot and the app can Start / Restart / Close it: run `comfyui/install_agent.ps1` once on each computer (the one-line command is at the top of that file). It installs `render_deck_agent.py`, which runs outside ComfyUI at sign-in and is reached at `https://<computer>.ts.net/agent`.

Download speed (helper, 2026-10-19): ⚙ › Model downloads picks Full speed (default) or Gentle (2 MB/s). The app POSTs /renderdeck/speed {mbps} to each online PC; the helper keeps it in custom_nodes/render_deck_speed.json and every download and PC-to-PC copy is paced by it. The other sync safeguards stay: copies only on need or ⇄ Check now, skipped over a relayed Tailscale link, 30-minute backoff.
