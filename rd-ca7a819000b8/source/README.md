# Render Deck (source)

Jordan's phone front end for ComfyUI. Blocks in the app build the ComfyUI API graph; Render sends it to the render computer.
Copyright (c) 2026 Jordan Brantner. All rights reserved.

- Live app: https://jbrantner.github.io/rd-ca7a819000b8/
- `comfy-app.html` is the whole app (one file, no doctype; `webbuild.py` wraps it into `../index.html` with the manifest, icons and offline helper).
- Release: edit `comfy-app.html`, run the tests, then `python3 webbuild.py ..` from this folder, commit and push `main`, and check that the "pages build and deployment" Action succeeds.
- `../tags.txt` is the Danbooru tag list behind the prompt suggestions (Illustrious and Pony styles): tag, category, count, aliases, a flag on adult or gore tags (`s` suggestive, `q` nudity, `e` sexual, `g` gore, then `w` when the tag's words have everyday senses too, so the reader takes it only in a plainly adult prompt), and each character's series. Rebuild it with `python3 make_tags.py danbooru.csv` from the a1111 tagcomplete list (link in the script), after `make_series.py` if the series need refreshing.
- `series.txt` (in this folder) is each character's series, made by `make_series.py` from the character tags themselves and the Character Select SAA lists (links and usage in the script).
- `../words.txt` is the English word list the prompt reader checks typos and word forms against (everyday words, other dictionary words, common names). Rebuild it with `python3 make_words.py EnglishDictionary.csv` (needs `pip install wordfreq english-words`).
- Prompt reader (the "Tags from your words" panel, between `READER START` and `READER END` in `comfy-app.html`): splits each comma piece into words, fixes typos only towards tag words (and never a real English word), knows word forms (casting/cast, sat/sit, hands/hand), finds tags whose words are spread over the sentence or turned round (casting an epic magic spell → casting spell; ribbon in her hair → hair ribbon), names characters and adds their series, reads names that are everyday words (link, fern) only when their series is about or they are written as a name, says no to "without glasses", and counts the people (a girl hitting another girl: 2girls; a girl and her little brother: 1girl, 1boy, brother and sister). Adult tags come only from their own words typed in order, or in another form, order or name once an adult word is typed, never from a typo, and everyday senses stay everyday (a sperm whale, nude lipstick, a naked blade, stripping wallpaper). A prompt that mentions children (child words, ages under 18, school years, and their typos) gets no adult tag, no adult word sent and no rating. The Rating row sets the style's rating tag from the words (Illustrious general → sensitive, nsfw or explicit, with nsfw taken out of the negative; Pony rating_questionable or rating_explicit), with a tap to keep the style's own. The user's own characters (🧍 Characters) and LoRA activation words go as typed and are counted, never read as a Danbooru character. The words with no tag go as words; Send as tags off sends the prompt as typed.
- `../chars.txt` says how often each character is drawn as a girl, boy or other, so the app can add 1girl / 2girls / 1boy / solo for the people named in a prompt. Rebuild it with `python3 make_chars.py` (asks Danbooru once per character; it resumes if stopped).
- Bump `APP_VERSION` in `comfy-app.html` on every release so a phone that resumes the app offers the update.
- Tests: `node tests/t_tags.js` runs the prompt reader on about 650 prompts (typos, word forms, characters, people counts, adult tags kept out of innocent prompts, the children guard, the rating) and checks its speed; `node tests/t_reader.js` runs it on 849 more SFW and adult prompts in `tests/fixtures/reader_cases.json` that must keep reading right; `NODE_PATH=$(npm root -g) node tests/t_flow.js`, `tests/t_lib.js`, `tests/t_queue.js`, `tests/t_farmapp.js`, `tests/t_draftfarm.js`, `tests/t_hidden.js`, `tests/t_chars.js`, `tests/t_pose.js`, `tests/t_suggest.js`, `tests/t_orbit.js`, `tests/t_comic.js` and `tests/t_3d.js` (needs Playwright), and `python3 tests/t_farm.py` for the helper's farm (and `tests/t_download.py` for resuming downloads) (needs aiohttp). It runs the app at phone size against a pretend ComfyUI and checks every graph against ComfyUI's node definitions; `t_queue.js` runs the queue across two pretend computers.
- Queue: every computer under ⚙ › Render computer takes renders while it's on and switched on in the queue (☰). Each render goes into the least busy computer's ComfyUI queue, so it keeps going when the app closes; while the app is open a free computer takes a render waiting on the other. Models and LoRAs are shared between the computers automatically through the helper's `/renderdeck/sync`.
- Draft mode (✎ by Render): each render stops at Painting › Draft stops at (about 45% of the steps by default) and saves to `RenderDeck/drafts`. Its picture is the clean guess at that step, like the live preview. Drafts wait under the main list; tick the good ones and Finish, which queues the full render built with the draft (same seed and settings, so it grows from the same start) with the finishing pass, upscale and face fix. It reruns the first steps rather than copying a saved latent between computers, so either computer can finish it.
- ⚡ Auto run (v.72, Jordan 2026-10-20: 'turn it on before I go to bed'): Run until Angles / Training shots / Picked set / Finished LoRA, then ▶ Start. The app builds its own graphs (turnaround; one per training shot with @SIDE/@BACK for the angle pictures the run finds; the quality pass with @IMG/@TAGS when it redraws) and POSTs them to the MiniMax PC's helper /renderdeck/auto/start. The helper (render_deck_auto.json, survives a ComfyUI restart) queues them on its own ComfyUI, finds the angles (silhouette width, as findSides) and the two sharpest moments per shot with PyAV + numpy, saves frames 1.5x (or redraws), picks the set (angles kept; shot frames by sharpness, blurry under 0.35x median and dHash near-repeats dropped, up to 30), writes captions to kohya\data\<trigger>\10_<trigger> and RenderDeck/datasets/<trigger>, then trains with kohya sd-scripts (found under %LOCALAPPDATA%\Comfy-Desktop\kohya; fp8_base, cached latents, Adafactor 1e-4 with text encoders at 5e-5, dim 32/alpha 16, 1600 steps (stronger since v.84: the first Librarian LoRA got her shirt right ~40% of the time); an optional style LoRA (⚡ Mix in style, e.g. AFKJ Style) is baked into a copy of the checkpoint with kohya's networks/sdxl_merge_lora.py (kohya\merged, reused; --base_weights crashed on Render) and the LoRA trains on that, so it learns only the character; ~3.6 s/step, 6.2 GB; one file named after the trigger (_v2, _v3 when taken), killed after two readings over 87 C; the farm skips that PC meanwhile) into models/loras as <trigger>.safetensors. The app polls /renderdeck/auto while the character sheet is open and puts the run's angles, shots and picks on the card (autoImport; images as 'sub/file.png [output]'). 🎓 Train the LoRA again (POST /renderdeck/auto/retrain {from, trigger, ckpt, style_lora}) copies the last run's kohya pictures under a new trigger word and trains only. Tests: tests/t_auto.py (helper, pretend ComfyUI and kohya), t_pipe.js.

Saved as an mp4 in `RenderDeck/characters/turn`. The spin's fit {cx, cy, cz, s, r} is kept on the clip; 🎨 Paint from the turnaround (turnViews) grabs six frames 60° apart and bakes them with those orthographic cameras (white background and 2.5 px in from it ignored). - Pose board (a recipe block): 3D OpenPose figures (y up, ground at 0, a figure about one unit tall) seen through a camera you orbit by dragging the empty board, or with Front/¾/Side/Back/Above/Below and Zoom; the picture sent is what that camera sees, with the face points OpenPose would not see (looking away, the far eye/ear in profile) left out. The board draws them as mannequins with a round head and a face. Figures are dragged on the phone (the neck moves a whole figure, a joint drags the joints below it), from starter poses, with mirror and size. Each figure can be given a character. The board is sent as an OpenPose picture to the chosen ControlNet (a union one like ProMax gets SetUnionControlNetType openpose), ending at 65% by default. Each figure with a character gets that character's tags in its own area of the picture (ConditioningSetArea + ConditioningCombine over the whole prompt), and the whole prompt gets the count tags (1girl, 1boy…) from the characters' tags.
- Farm: when the computer named Render has the newest helper, it keeps the queue itself (`/renderdeck/farm`, saved in `render_deck_farm.json`) and hands each render to whichever computer has nothing to do, and keeps the models matched, with the app closed. The app then only adds, cancels and shows renders. Without it the app does this itself while open.

## Setup on the render computer
1. Install Tailscale on the render computer and the iPhone, same account on both.
2. Tailscale admin page > DNS: turn on MagicDNS and HTTPS certificates.
3. Start ComfyUI with `--enable-cors-header "*" --preview-method auto`.
4. Optional, for "Add a model or LoRA": copy `comfyui/render_deck_models.py` into `ComfyUI/custom_nodes/` and restart ComfyUI. It downloads Civitai / Hugging Face links and receives files from the phone (.safetensors only). For Civitai models that need sign-in, put a Civitai API key in `CIVITAI_API_TOKEN` or in `civitai_token.txt` next to the helper.
5. Run `tailscale serve --bg 8188` once and paste the https address it prints into the app (⚙ > Connect).
6. Optional, to share renders between computers: set each computer's ComfyUI output folder (Comfy Desktop's output folder, or `--output-directory`) to the same Dropbox folder, and put this computer's name in `custom_nodes/render_deck_pc.txt` (for example `Output_Main`). The helper then saves into that subfolder, the renders browser shows every computer's pictures, and Delete removes them from all of them (Dropbox's Deleted files can restore them).
7. Hidden (🙈 at the top): a second workstation with its own recipe, strip and renders list. Its renders save into `Hidden` folders (`Output_Main/Hidden/…` with a shared folder) and are left out of the normal renders list (needs the helper from 2026-10-18 or later; older helpers still work, the app filters instead).
7. Optional, so ComfyUI comes back after a crash or reboot and the app can Start / Restart / Close it: run `comfyui/install_agent.ps1` once on each computer (the one-line command is at the top of that file). It installs `render_deck_agent.py`, which runs outside ComfyUI at sign-in and is reached at `https://<computer>.ts.net/agent`.

Download speed (helper, 2026-10-19): ⚙ › Model downloads picks Full speed (default) or Gentle (2 MB/s). The app POSTs /renderdeck/speed {mbps} to each online PC; the helper keeps it in custom_nodes/render_deck_speed.json and every download and PC-to-PC copy is paced by it. The other sync safeguards stay: copies only on need or ⇄ Check now, skipped over a relayed Tailscale link, 30-minute backoff.

Model sync: ⚙ › Model downloads › Keep both in step (default) has the farm on Render compare both computers every half hour and copy what one lacks (one file at a time, at the picked speed, direct Tailscale link only); Only when needed copies just when a render needs a model or on ⇄ Check now. Kept in each helper's render_deck_speed.json ('auto').
